# Communication parity push — 2026-11-15

Base: `8dac51dcb`; integration branch: `yolo/gpui`. The main agent reviews,
merges and validates worktree commits. This push expands six major areas; it
does not declare complete Fluxer parity or replace the existing release gates.

Correct operation is the first requirement. UI/UX is the second: use the classic
Fluxer implementation as the protocol and interaction reference, with Discord's
familiar density where compatible. Do not land placeholder action banks or a
second interaction model that will need replacing. Keep ordinary chat readable.

## Integration and verification

- Local source defines HTTP/gateway methods, payload omissions, subscriptions,
  response shapes, permissions and account lifecycle. No guessed endpoints.
- Keep callbacks and IO off the GPUI thread, bound caches/queues, and fence stale
  asynchronous work. Preserve existing optimistic messages, drafts, undo,
  profile click boundaries, voice/stream controls and permissions.
- Build through `/tmp/fluxer-push-cargo` (a flock-serialized wrapper using the
  existing disk-backed offline target); do not rebuild dependencies into the
  installed executable's target directory.
- Run targeted source-backed tests per slice; the integrated branch must pass
  `scripts/verify.sh`, formatting, strict workspace Clippy and the parity audit.
- GUI checks use owned synthetic fixtures and explicit test sinks. Do not send
  production messages, edit relationships/settings on a real account, join calls,
  capture personal audio or change global audio defaults to prove a feature.
- Record real-account, hardware, cross-client and subjective checks in REVIEW.md.
  Multi-stream acceptance remains deferred at the user's request.
- Update this file with landed commit IDs, actual supported scope and remaining
  work at integration. A partial backend or static mock is not a completed UI.
