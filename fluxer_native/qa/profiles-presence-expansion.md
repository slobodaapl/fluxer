# Profile and presence expansion

The expanded profile reuses the compact profile's loaded snapshot and image resources. The modal presents only data already returned by the profile request, including biography, membership dates and guild roles. It preserves the existing direct-message and relationship confirmation flows. `Escape` closes it, backdrop clicks dismiss it, and its scroll area is bounded by the viewport. The entry is omitted for webhook identities.

Source references: `fluxer_app/src/features/user/models/Profile.ts`, `fluxer_app/src/features/user/state/CustomStatus.ts`, `fluxer_app/src/features/user/hooks/useCustomStatusDraft.tsx`, `fluxer_app/src/features/app/config/TimeWindowPresets.ts`, and `fluxer_app/src/features/user/state/StatusExpiry.ts`.

Pending live GUI review: narrow windows, long biographies and roles, image loading, keyboard navigation, backdrop dismissal and relationship confirmation. No live account mutations were performed.

The custom status editor uses the existing emoji catalog and source duration presets. It sends either `emoji_id` or `emoji_name`, and computes `expires_at` at save time. Pending live GUI review includes emoji picker focus and custom status expiry.

Timed presence resets use the source `status_resets_at` and `status_resets_to` fields, with a one-second expiry poll; custom status is omitted from gateway presence after expiry. Pending live review includes expiry during reconnect and account switching. The current native client does not yet expose a system-wide idle signal. In particular, window focus is not evidence of system idleness; the client does not infer AFK from it. Biography links use the existing message navigation and trust policy; concealed spoiler spans remain concealed. Keyboard traversal of biography links and richer inline formatting need further work.

Classic desktop uses Electron `powerMonitor.getSystemIdleTime` (`fluxer_desktop/src/main/IpcHandlers.ts`) and combines it with local input in `fluxer_app/src/features/ui/state/Idle.ts`. Wayland's `ext_idle_notifier_v1` version 2 provides input-only threshold notifications tied to a seat; they begin their timeout upon creation, so reconnect may delay idle detection. Version 1 honors idle inhibitors and is not equivalent to input inactivity. Mutter's IdleMonitor provides elapsed idle time where that D-Bus service is available. Neither backend is wired here. logind's `IdleSinceHint` records when a desktop-provided idle hint changed, not when input last occurred. References: the cached `wayland-protocols` staging `ext-idle-notify-v1.xml` and https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html.
