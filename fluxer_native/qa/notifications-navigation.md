# Native notifications, quick switcher and inbox

Source references: `Notification.ts`, `AccountNotificationGate.ts` (other-account gate), `MessageNotificationPreview.ts`, `Sound.ts`/`SoundUtils.ts`, `GuildMatureContentAgree.ts`, `QuickSwitcherModal.tsx`, `QuickSwitcherResultGenerators.ts`, `UnreadInboxVisibility.ts`, `MentionFeed.ts`, and `RecentMentionCommands.ts`.

No real notification, sound, session restore or account mutation was used in this lane. Notification tests use a private fake sink; transport tests use private HTTP/WebSocket fixtures. Root owns final GUI and physical keyboard review.

Use explicit `--demo` with one fixture variable:

- `FLUXER_QUICK_SWITCHER_DEMO=''`, `#gen`, `!voice`, `@al`, or `*work` opens the compact modal. Check Ctrl+K/Ctrl+T, Unicode filtering, arrow/wheel selection, selected row visibility, Enter release, IME composition, Escape focus restoration, and small-window bounds. Opening a user uses the existing real OpenDm command outside Demo. Channel selection preserves the old draft. Results come from known channels, cached friends/members, communities and recent navigation; this does not claim a global user directory or cross-account switcher.
- `FLUXER_INBOX_DEMO=unread|mentions|error` opens the source-style inbox. Check the measured button anchor, outside dismissal, clicking the same opener to close, tabs, filters, wheel/arrows, Enter release, loading/error/retry, read markers and row jumps. Demo mention cards are explicitly synthetic and labelled offline.

The real mention feed uses authenticated `GET /users/@me/mentions?everyone=…&roles=…&guilds=…&limit=50[&before=…]`. It preserves fetched data on failures, cancels stale requests, retains cache across close/reopen, merges live mentions and message edits/deletes, and keeps detached results out of timeline/read acknowledgements. Opening a mention requests its actual history target; only the existing visible-message policy acknowledges it. Filters read the source synced preferences. Unreads use the gateway's current channel/read-state hierarchy; inherited mutes hide ordinary unread rows while mentions remain visible. Advanced unread-badge customization is outside this default policy.

Desktop delivery is opt-in and runs on a background freedesktop session-bus worker with safe strings, exact click targets and account fencing. File preparation, configuration I/O and output-only bundled sounds run off GPUI. Configuration uses bounded reads and atomic private files; relative XDG roots are rejected. Service, sound and preference failures are visible in notification settings. Focus clears that channel's delivered alerts; account changes clear previous alerts and stop their sounds. Source mute/mention settings, blocked/own messages, DND/reset expiry, notification-suppression flags, streamer/privacy settings and sound preferences apply. Same-channel sounds default off. Sound overrides replace master volume before the source headroom/cap.

Mature-content previews require the effective channel/category/community consent and an allowed account. Regional age-check GeoIP state is not projected by the native client yet; do not claim complete geo-restricted mature-content parity. Unknown or inaccessible mention channels remain hidden until metadata is available; this slice does not add thread metadata discovery.

Validation includes the source authenticated mention route/filters/cursor, stale account/request fencing, append deduplication, failure/cache retention, live edit/delete updates, unchanged read cursors, inherited unread hierarchy, source synced preferences, notification replay suppression, fake-service failures, safe previews and private bounded configuration files. The strict public-controller read/notification fixture now explicitly handles the previously added source slowmode GET.
