# Linux desktop icon and system tray — 2026-11-18

Implemented on `yolo/gpui`, with source behavior taken from `DesktopTray.ts`,
`TrayIconImage.ts`, `Window.ts` and `DesktopConfig.ts`. The tray is a Linux
StatusNotifierItem/dbusmenu service, available to compatible desktop panels.
Defaults match classic Fluxer: tray shown, close-to-tray on, colored tray off,
and start minimized off. Settings are device-local in `interface.json` and retain
legacy preferences, atomic saves and failure rollback.

Close hides the existing GPUI window only while a tray host is registered. The
client, drafts, gateway and active calls remain alive. Explicit tray Quit or
Ctrl/Cmd-Q exits. If the host disappears or the icon is disabled while hidden,
the window is restored; without a host Close exits normally. Startup hiding is
conditional on a working host. Normal OS minimize remains normal minimize;
minimize-to-tray is not exposed because the Wayland toplevel protocol provides no
reliable minimized notification.

The tray menu provides Show/Hide, Desktop settings, presence, current-call
mute/deafen/disconnect, Copy Build Info, Restart and Quit. Call commands carry the
observed account and generation into the existing worker control contract.
Presence commands reject an old account. Menus reflect authoritative state rather
than optimistic local mute state. Demo Restart is omitted to avoid relaunching a
demo as a real-account process. Tray activation raises inactive windows; a second
activation in a double click keeps the window shown. Wayland activation tokens
are forwarded where available; focus remains subject to compositor policy.

A separate local desktop activation interface raises the existing window on
ordinary launcher re-execution. It claims no classic Fluxer bus name and has no
capture/join capability. No D-Bus auto-start file is installed. The installer
`scripts/install_desktop_entry.py` writes only Native's per-user desktop entry and
hicolor icons, matching `app.fluxer.Native`; it does not replace classic Fluxer.

GPUI's reversible Linux hide/show implementation keeps the same window/entity.
Wayland unmaps and remaps through a new XDG configure handshake, restores toplevel
attributes, fences stale remap callbacks and suspends hidden draws. X11 withdraws/
remaps the existing window. Non-Linux hide hooks report unsupported; their tray
settings are disabled. Windows/macOS tray integration is still future work.

## Evidence

`target/qa/tray-2026-11-18/` records owned Wayland captures, source/contract tests,
private-host lifecycle results and final verification. The combined gate passes
681 tests, zero failures, 14 opt-in ignored, plus audit/format/strict Clippy.
The explicit `--demo --demo-tray` fixture runs a tray without claiming the normal
window activation bus. `--demo-tray-start-minimized` additionally exercises the
actual startup policy without writing a live preference.

Real microphone/call continuity, subjective panel appearance, X11 behavior,
compositor-specific focus/fullscreen behavior and host reconnect need broader
manual acceptance. Classic account switching, custom CSS/update controls and
numeric taskbar overlays are not supplied by this tray increment.
